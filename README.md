# hxwl-09 半导体洁净室巡检

洁净等级阈值、粒子计数与异常处理看板。采样批次、仪器校准、阈值政策、异常处置共用**同一套判定**（`src/domain/`）。

## 技术栈

React + Vite + TypeScript + CSS

## 本地运行

```bash
npm install
npm run dev     # 开发端口 5109
npm test        # 判定规则测试（vitest，9 条）
npm run build
```

## 统一判定口径（src/domain）

- **体积换算**：体积(L) = 流量(升/分钟) × 时长(秒) / 60；每立方米计数 = 原始计数 × 校准系数 ÷ 体积(m³)。采样 30 秒~5 分钟都先换算再判定。
- **当时阈值版本**：判定采用采样结束时刻生效的阈值版本（`resolvePolicy`），校准同理（`resolveCalibration`）。
- **<2L 待补采**：体积不足 2 升的批次判定为「待补采」，不生成异常处置、不计入异常指标；巡检员可补录足量批次。
- **依据更新重算**：发布新阈值版本或录入新校准后，未签认批次按新依据重算（可能新开/自动关闭处置单）；已签认批次冻结，保留原值和依据。
- **冲突**：同一次采样（点位+采样时刻）现场与中心重复提交时，首份有效记录入库，后到者留冲突草稿、不参与判定。
- **断点重试**：批次 id 即幂等键，上传失败后重发未完成批次即可；重放不新增处置或审计。
- **角色**：巡检员可提交/补录，班组长可签认与发布依据，审计员只读（越权抛 `PermissionError`）。
- **同一出口**：看板指标、异常处置单、CSV 导出都读 `record.determination`，三处显示必然一致。

## 演示脚本（页面上可点）

1. 「模拟上传（中途断线）」→「从断点重试未完成批次」：观察 U-02 重放零副作用、U-04 成为冲突草稿。
2. 待补采行点「补录」（巡检员）：生成足量补采批次。
3. 切到班组长：「发布加严阈值」→ 未签认批次重算（B-2605 转超限）；「录入 P-01 新校准 ×0.92」→ 重算后不再超限的处置单自动关闭；已签认的 B-2604 始终保留原值与依据。
