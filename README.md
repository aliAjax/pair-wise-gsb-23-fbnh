# hxwl-09 半导体洁净室巡检

粒子采样批次、仪器校准、阈值政策、异常处置统一判定系统。
看板、异常处置、CSV 导出共用同一个判定内核（`evaluateBatch`），结果永远一致。

## 技术栈

React 19 + Vite + TypeScript（无后端，状态持久化在浏览器 localStorage）

```bash
npm install
npm run dev        # 开发：http://localhost:5109
npm test           # 判定规则 25 项 + 状态流转 45 项自测
npm run build      # 类型检查 + 生产构建
```

## 统一判定规则

| 主题 | 规则 |
| --- | --- |
| 体积换算 | 采样体积 = 流量(L/min) × 时长(s) ÷ 60；粒/m³ = 原始计数 × 校准系数 ÷ 体积(L) × 1000 |
| 阈值版本 | 采用**判定当时有效**的阈值版本；签认时把当时版本、系数、原值冻结进快照 |
| 低体积 | 体积 < 2 L 的批次标记「待补采」，**不参与异常判定**；补采批次入库后原批次标记已补采 |
| 依据更新 | 校准系数或阈值更新后，**未签认**异常按新依据重算；**已签认**保留原值原依据，仅旁示现行重算值 |
| 现场/中心并发 | 同一次采样（房间+采样时刻相同）首份有效记录入库，后到者留草稿并显示冲突，可丢弃或改时刻作为新采样 |
| 断点续传 | 上传失败批次留在队列，恢复网络后从断点重试；重放幂等——**不新增处置、不新增审计**，已入库批次不重复处理 |
| 权限 | 巡检员提交/补录/补采、班组长签认、厂务工程师发布校准与阈值、审计员只读 |

未签认异常由判定内核在读时实时算出（不落库），因此阈值/校准重算与上传重放天然不会产生
重复处置记录；处置单在班组长签认时才落库并冻结快照。

## 页面

- **判定看板**：KPI、等级/区域/判定筛选、统一判定表、补采入口、CSV 导出
- **采样录入**：30 秒–5 分钟时长、现场/中心渠道、实时体积与浓度预览；可关闭「网络正常」制造失败批次
- **异常处置**：未签认异常按现行依据显示，班组长签认后冻结，旁示现行重算值
- **冲突与上传**：冲突草稿处理、上传队列断点重试
- **校准与阈值**：校准系数与阈值版本发布（厂务工程师）
- **审计日志**：全角色只读；重放/重算不产生审计

## 代码结构

```
src/domain/
  types.ts        领域模型（批次/校准/阈值/处置/审计）
  evaluation.ts   统一判定内核：体积换算、版本选择、冻结/重算
  flow.ts         纯状态流转：并发去重、幂等重试、补采、签认、发布
  seed.ts         演示数据（含翻转、冻结、低体积、冲突、失败批次）
src/state/store.tsx  React 封装 + localStorage 持久化
src/ui/           看板、表单、处置、冲突、政策、审计组件
scripts/          判定规则与状态流转自测
```
